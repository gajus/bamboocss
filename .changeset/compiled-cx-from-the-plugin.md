Join the classes compiled code merges at runtime with the plugin's `cx`, written for the project's `prefix`, instead of
the `cx` the module imported. For a workspace design system that was its own `styled-system`'s `cx`, generated by
another release or for that package's config. `cx` merges by reading class names past the prefix it was generated for,
so one generated for another prefix read none of the app's classes as atoms: `cx(button({ size }), className)` kept the
recipe's padding beside the one `className` passed to replace it, and the stylesheet's order chose between them, with no
error.

In a compiled module, `cx` imported from a `styled-system` is now bound to the one `virtual:bamboo/compiled` serves, so
a call the compiler writes, one it leaves as written and any other read of `cx` all reach it, and `export { cx } from` a
`styled-system` re-exports it.
