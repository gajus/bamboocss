Refuse a `styled-system` generated by another Bamboo release where code the Vite plugin compiled meets it, instead of
selecting no classes. A compiled recipe call imports `cvaMap` and `splitProps` from `styled-system/css` by names that
include the release, such as `cvaMap$bamboo_1_64_11`, and only a `styled-system` generated by the same release exports
them. The tables `cvaMap` reads changed format three times in 1.64.8, and the `cvaMap` of 1.64.7 reads a table 1.64.8
writes for a wide recipe as selecting nothing: the element lost its recipe's classes, with no error.

The plugin writes the project's own `styled-system` before anything imports it, so that one always matched. One it does
not write, such as a workspace package's own or one that `bamboo codegen` from another version wrote, now fails the
build with `"cvaMap$bamboo_…" is not exported by …`, and fails to load in development, until it is generated again by
the plugin's release.

The `styled-system/css` barrel no longer exports the two helpers by their own names, which only the compiler imported.
`styled-system/css/cx` still exports them.
